# Poolnews — a fantasy hockey pool site

Static site for Yanick's ~11-pooler hockey pool. **No server, no database, no
build step for the pages themselves.** It works opened straight from disk *and*
published to GitHub Pages.

- Live: https://royalgre.github.io/Poolnews/ · Repo: `RoyalGre/Poolnews` (public)
- The interface is **French**. Match it — new UI strings, page titles, commit
  messages. The README and code comments are English.

## Pool rules (encoded in `assets/core.js`, `scoreRoster()`)

- 12 picks per pooler, a player belongs to exactly one pooler.
- Goals + assists = 1 pt. **Best 10 of the 12 count.**
- **At least one defenceman among the counting 10.** If the natural top 10 is
  all forwards, drop the 10th and promote the best D on the bench — the
  cheapest legal swap.

`index.html` redirects to the standings. `assets/core.js` is shared by all the
app pages: player index, search, saved state, **scoring**, weekly history.

**Theme:** `assets/theme.css` holds the only palette and the three faces;
`assets/theme.js` stamps the light/dark choice in `<head>` before paint.
`site.css` styles components and keeps old token names as aliases
(`--bg: var(--ground)`). Chart colours can't be CSS vars — `core.js` carries two
12-hue sets and `colorFor()` picks per theme.

## Routine tasks

```powershell
# stats refresh — the one to schedule. Exits in ~1s if no games were played.
powershell -ExecutionPolicy Bypass -File Y:\HockeyPool\update.ps1

# picks changed (draft day, a trade) — bakes localStorage into data/pool.js
powershell -ExecutionPolicy Bypass -File Y:\HockeyPool\publish-pool.ps1

# ALWAYS before pushing
powershell -ExecutionPolicy Bypass -File Y:\HockeyPool\run-selftest.ps1
```

`update.ps1` picks a gear itself: **light** (~40 requests) most runs, **full**
(~160) every 24h or with `-Full`. Other flags: `-Force`, `-WithAdvanced`,
`-Quiet`. It finishes by restamping cache tags.

## Hard-won rules — breaking these has caused real bugs

**Data ships as `.js`, never `.json`.** A `file://` page may load a sibling
`<script src>` but `fetch()` of a local `.json` is CORS-blocked. Each data file
assigns a `window.NHL_*` global.

**PowerShell scripts must be UTF-8 *with BOM*.** Windows PowerShell 5.1 reads a
BOM-less `.ps1` as ANSI: accents and em-dashes become mojibake and blocks can
silently fail to run. This once made a self-test print PASS on a deliberately
broken input. If a tool strips the BOM, put it back.

**Every local asset link carries a content hash** (`site.css?v=7eb348fc`),
written by `stamp-assets.ps1`. Without it a returning visitor loads today's page
against yesterday's cached stylesheet — that is what once rendered the rink
black with no roster panel. It runs automatically inside `update.ps1` and
`publish-pool.ps1`; run it by hand after editing anything in `assets/`.
`run-selftest.ps1` fails on a stale tag.

**Never edit `pool-records.html` directly.** It is generated by
`build-report.py` from `pool-history.json` + `pool-records.template.html`. Edit
the template — including the nav, or the next rebuild drops the site's tab bar.

**Pooler names are `First L.`** Two Martins collide, stored as `Martin Pe.` and
`Martin Pr.`; careers are keyed on the exact string, so merging fuses two
careers. Canon lives in the `poolers` block of `pool-history.json`.

### Windows PowerShell 5.1 traps (all guarded in the scripts)

- `Invoke-RestMethod` decodes as ISO-8859-1 when the response has no charset,
  mangling `Fransén`. Use `Invoke-WebRequest -UseBasicParsing` plus
  `[Text.Encoding]::UTF8.GetString($resp.RawContentStream.ToArray())`.
- `ConvertTo-Json` turns an array from `New-Object type[] n` into
  `{"value":[...],"Count":n}`. Wrap it in `[int[]]@(...)`. Silent, and it breaks
  the browser.
- The stats API returns rows in an **unstable order without an explicit `sort`**,
  so paging silently skips and duplicates. `limit=-1` avoids paging entirely but
  caps at **10,000 rows** — stay well under it or rows vanish with no error.

## NHL API notes (public, no key)

- `api.nhle.com/stats/rest/en/skater/summary` with
  `isAggregate=true&isGame=true&cayenneExp=gameDate<="YYYY-MM-DD"` gives
  **season-to-date totals as of any date** — that is how 28 weekly snapshots get
  backfilled in ~40s.
- `isAggregate=false&isGame=true` with `playerId in (...)` returns per-game rows,
  so a season of game logs for ~940 players costs **24 requests, not 940**.
- **Coordinates exist only in the per-game play-by-play**
  (`api-web.nhle.com/v1/gamecenter/<id>/play-by-play`) — one request per game.
  `build-goals.ps1` therefore banks finished games and refetches only new ones;
  a full season is ~1,300 requests once, then ~10 a night.

## Testing

`run-selftest.ps1` injects a suite into a throwaway copy of each page, runs
headless Chrome with `--dump-dom`, and scrapes a `#TESTOUT` div. Four suites,
plus navigation and cache-tag checks. Exit code 1 gates a bad change.

Chrome: `C:\Program Files (x86)\Google\Chrome\Application\chrome.exe`. The
throwaway copies must sit **next to** the originals — the pages load `assets/`
and `data/` by relative path. No Node on this machine.

The strongest check: the Pooleurs page counts individual goals while
`history.js` sums weekly deltas — **no shared code** — and the suite asserts all
11 poolers × 28 weeks agree.

## Open questions

- **Whether goalies should be draftable at all.** Under pure G+A a goalie scores
  ~0. They are currently in the pickable list. Unanswered since 2026-09-05.
- **How the mini-game's picks get collected.** The game itself is built and
  answered (see below); what is still open is the backend. Firebase project
  `poolnews-846e0` exists with a web app registered, but `defi.js` still reads
  `window.DEFI_PICKS` from a hand-written `data/defi.js`. All pick access goes
  through `picksFor()`, so wiring Firestore touches that one function.
- **Firestore is open with no guard, until 2026-12-31.** `firestore.rules` in
  this repo is the source of truth. The repo is public, so anyone who finds the
  project id can read or overwrite every pick. Deliberate and temporary — the
  expiry date is there so it cannot stay open by forgetting. The file's comments
  carry the two-line change that swaps it for a shared passphrase.

## The weekend mini-game — settled 2026-09-13

Poolers predict the **percentage** split of goals scored **Thursday, Friday and
Sunday** across three zones: left slot / right slot / everywhere else. Scoring is
the **sum of the three absolute errors**; lowest total wins. Saturday is excluded
on purpose — it is the big hockey night and would swamp the other three days.

A slot is within **34 ft of the goal line** (x ≥ 55, net at 89) and within
**±22 ft** of the centre axis. Re-validated against all 8,086 goals in
`goals.js`: 37.6 / 42.1 / 20.3 overall, and across the 26 Thu/Fri/Sun weekends
the means are 37.4 / 43.3 / 19.3 with standard deviations 6.2 / 6.8 / 3.7.
Stable enough to reason about, variable enough that guessing the season average
rarely wins — which is the point.

A weekend is keyed by **backing up to its Thursday**, not by ISO week. Verified:
no bucket spans past Sunday, and the three month-crossing weekends group
correctly.
